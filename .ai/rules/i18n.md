# Messages

next-intl, Czech and English, one catalog each in `apps/web/src/i18n/messages/`.
`messages-parity.test.ts` enforces this file. Deep reference:
[docs/ui.md § Glossary](../../docs/ui.md#glossary).

## Rules

- **Same keys, same ICU arguments and tags in both locales**; no empty strings.
- **A key looked up with a runtime value is a family** (``t(`status.${s}`)``): list every
  value in the test's `FAMILIES`, exactly.
- **A key no source names fails.** Delete it with its last use.
- **One word per thing.** The glossary's losing words fail the test: no "přihláška" (booking is
  rezervace), "útvar" (oddělení), "dodavatel" (poskytovatel); in English no "location" (room),
  no bare "IČO", no "contract" (offering). "Přihlásit se" is signing in and stays.
- **Every message ships to every page**, the landing page included: no real course codes or
  names as examples (use `KURZ-01`), no personal data.
- **Dates and money are formatted one way in both languages** (`@muni/utils/format`):
  `17.10.2026 9:00`, `1 200,00 Kč`. Rates print floored (`formatRate`), never
  `formatPercent`.
- **After renaming keys in bulk, read the rendered pages**: a scripted rename can collide two
  keys and still pass the parity test.
